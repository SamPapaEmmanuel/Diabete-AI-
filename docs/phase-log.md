## Phase 1: Foundation

Date: 2026-10-26. Status: implementation and local validation complete; the formal exit check awaits a passing hosted GitHub Actions run.

Read the Phase 0 log, specification, decision record, repository instructions and Phase 1 prompt before coding. Used the frontend-design and ui-ux-pro-max skills within the agreed solid-colour, typography, accessibility and layout rules. Implemented only the foundation phase.

Added `apps/web` with React, strict TypeScript and Vite. The Report, History and Account screens use a desktop left rail and mobile bottom navigation, shared light/dark tokens, Source Sans 3 and Source Code Pro at two weights, and Lucide line icons at a fixed stroke width. Font licenses are included. Loading, empty, service-error and offline behavior are present, along with keyboard navigation, a skip link, labelled controls and public theme preferences. All application copy is in `content/locales/en-GH.json`. Report upload is explicitly unavailable because ingestion belongs to Phase 2.

Added `apps/api` with FastAPI, typed request/response schemas, redacted validation errors, no-store responses and health/readiness endpoints. The local authentication skeleton supports registration, single-use email verification, sign-in, password recovery and sign-out. It hashes passwords with Argon2id, stores only token hashes, binds CSRF tokens to the current session, checks origins, applies account/IP request limits, rotates sessions and revokes sessions on password reset. Successful sign-ins clear failed-attempt counts. Development email messages are private local outbox files, never external sends. Hosted production mode is deliberately unavailable until its mail transport and configuration are reviewed.

Added SQLAlchemy models and an explicit Alembic migration for ten tables covering accounts, one report subject per account, sessions, action tokens, rate limits, consents and saved-report/observation/interpretation/retained-source records. Composite ownership constraints prevent linking another account's subject, consent or retained source. Decimal measurements use unrestricted PostgreSQL numeric storage and preserve source text and comparison operators. No guest payload or raw OCR table was added. Application report workflows and the clinical rule engine remain for later phases.

Added pinned npm dependencies and a uv lockfile, Prettier/ESLint and Ruff formatting/linting, TypeScript and mypy checks, development PostgreSQL/Redis Compose configuration, a loopback-only optional PostgreSQL binary launcher and a GitHub Actions workflow. Runtime downloads, caches, local databases, outbox messages and browser artifacts are ignored. Updated the README with installation, startup, migration and test instructions. Local runtimes were placed under `.runtime` because Node.js, Python and PostgreSQL were initially unavailable on PATH; existing repository files and unrelated editor settings were preserved.

Local validation passed: 15 pytest tests, six Vitest tests and eight Playwright tests. PostgreSQL migration upgrade, downgrade, re-upgrade and model-drift checks passed. Prettier, ESLint, Ruff formatting/linting, TypeScript, mypy and the Vite production build passed. Tests cover token reuse and expiry, CSRF/origins, session rotation/idle expiry, recovery and revocation, throttling, redacted validation, exact decimal storage, ownership/cascades, no gradients, token contrast, navigation, themes and offline behavior. Desktop/mobile browser flows cover registration, local email verification, sign-in, reload, password recovery and sign-out. Automated accessibility checks found no violations on all three screens in both themes; this is not a full manual WCAG audit.

The local database tests ran against the packaged PostgreSQL 18.4 binaries. Browser checks used the installed Microsoft Edge Chromium engine; the CI workflow provisions PostgreSQL 17.6 and Chromium, so those hosted results still need verification. Inspected desktop/mobile previews under `.runtime/previews`. API tests emit one upstream Starlette/httpx deprecation warning while passing. Initial browser checks exposed password-label semantics and startup sensitivity; corrected the label, added bounded requests, reduced test concurrency and tested the built application.
